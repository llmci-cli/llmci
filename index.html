How It Works

Set up in five minutes.
Protected on every PR.

No platform to sign up for. No SDK to integrate. No data leaving your infrastructure. A CLI that reads a YAML file and exits 0 or 1. Your first eval runs in under five minutes.

01

Define your evals

Add a scaffold.yaml to your repo. Point it at your eval dataset, pick metrics, set thresholds.

02

Run in CI

One step in your GitHub Action or CI pipeline. Scaffold runs evals and compares against your main branch baseline.

03

Gate every PR

Pass or fail. If quality degrades beyond your thresholds, the PR is blocked with a detailed regression report.

02
Config as Code

Your LLM quality,
version-controlled

One YAML file defines everything. Deterministic metrics for classification. LLM-as-judge for open-ended generation. Works with any model, any framework, any language.

  • ⇆

    Black-box testing

    Runs your pipeline as a subprocess. Scaffold doesn't need to know your stack—just inputs and outputs.

  • ☰

    Multiple judges

    Exact match, F1, accuracy for deterministic tasks. LLM-as-judge with custom rubrics for generation.

  • ◈

    Upstream-aware

    Pipeline-level evals catch regressions from retrieval, preprocessing, and data changes—not just prompt edits.

  • ≡

    Flexible thresholds

    Absolute quality floors or max-regression limits. Smoke-test subsets for fast CI, full suites on merge.

scaffold.yaml
version: 1 target: command: "python run_prompt.py ..." evals: - name: ticket-classification dataset: ./evals/tickets.jsonl judge: exact_match metrics: - name: f1_macro threshold: 0.93 mode: absolute - name: response-quality dataset: ./evals/responses.jsonl judge: type: llm rubric: - id: factual_accuracy prompt: "Is the response correct?" metrics: - name: rubric_pass_rate threshold: 0.03 mode: max_regression

Agentic Workflows

Test agents,
not just prompts

Agents make sequences of decisions—tool calls, routing, branching—often across multi-turn conversations. A single output check isn't enough. Scaffold evaluates the full trajectory: outcome, efficiency, tool usage, and cost, per-turn and per-conversation.

✓ Outcome judging

LLM-as-judge evaluates whether the agent achieved the correct final result, not just whether individual steps looked right.

→ Trajectory analysis

Was the execution path efficient and logical? Catch agents that produce correct results through wasteful or dangerous paths.

‖ Constraint enforcement

Set budgets on tool calls, tokens, and latency. Flag required and forbidden tools. Deterministic checks, no LLM needed.

⇄ Agent migration

Trajectory-aware optimization identifies where the new model diverges and tunes the right component—system prompt, tool descriptions, or step instructions.

Dataset Creation

Build your eval dataset
in an afternoon, not a quarter.

These are CI gates, not training sets. 200 carefully chosen examples beat 2,000 auto-generated ones. Start with manual curation guided by coverage analysis, then expand with automated generation when you need more.

⬆

Import production logs

Export logs from Langfuse, Arize, or your own system. Scaffold identifies successful runs, selects diverse examples, and converts them into eval scenarios with inferred constraints.

☆

Generate from specs

Provide tool definitions and a system prompt. Scaffold generates realistic scenarios that exercise your full tool surface with coverage targets.

↔

Augment & expand

Start with 20 hand-curated examples. Generate perturbations—rephrased inputs, edge cases, combined intents—to build a statistically significant dataset.
